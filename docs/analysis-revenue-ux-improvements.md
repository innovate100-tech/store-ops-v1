# 매출 흐름 분석 — 사용자 입장 개선안

현재 `/analysis/revenue` 페이지를 **사용자(매장 운영자·관리자)** 관점에서 분석한 개선 제안입니다.

---

## 1. 기간 선택

| 현황 | 사용자 관점 이슈 | 개선 제안 |
|------|------------------|-----------|
| 최근 7일 / 30일 / 90일만 선택 가능 | "이번 달 전체", "지난달 전체"를 보고 싶을 때 30일 선택 후 날짜를 맞춰야 함 | **이번 달**, **지난 달** 옵션 추가 (해당 월 1일~말일 자동 설정) |
| 기간이 "오늘 기준"인지 불명확 | 보고서 공유 시 "언제까지 데이터인지" 헷갈릴 수 있음 | 기간 옆에 **"(오늘 기준)"** 또는 **"~ 오늘"** 문구 표시 |
| 사용자 지정 날짜 없음 | 특정 이벤트 기간(예: 12/20~12/26)만 비교하고 싶을 때 불가 | 단기: **시작일·종료일 date picker** 추가 (장기: 별도 스펙) |

---

## 2. 교육 배너

| 현황 | 사용자 관점 이슈 | 개선 제안 |
|------|------------------|-----------|
| 탭마다 배너가 항상 펼쳐져 있음 | 한 번 읽은 사용자는 스크롤만 늘어나서 차트/표를 보기 불편 | **접기/펼치기** 또는 **한 번 닫으면 해당 탭에서만 접힌 상태 유지** (세션 또는 로컬 저장) |
| 5탭 모두 같은 형태 | "이미 이해한 탭"은 배너가 방해 요소로 느껴질 수 있음 | 배너 높이를 줄이거나, "요약 1줄 + 더보기" 형태로 첫 노출 최소화 |

---

## 3. 현재 보고 있는 기간 인지

| 현황 | 사용자 관점 이슈 | 개선 제안 |
|------|------------------|-----------|
| 기간 선택은 상단에만 있음 | 탭을 바꾼 뒤 스크롤하면 "지금 어떤 기간 데이터인지" 다시 확인하려면 위로 올라가야 함 | 각 탭 콘텐츠 **맨 위(배너 위 또는 아래)**에 **"기간: 2025-01-01 ~ 2025-01-30"** 같은 한 줄 표시 |
| 로딩 중에만 "로딩 중…" 표시 | 데이터 갱신 중인지, 기간 변경 후 적용됐는지 애매할 수 있음 | 기간 변경 시 **짧은 로딩 표시**(스피너 등)를 탭 영역에서도 보이게 하거나, "기간 적용됨" 토스트 |

## 4. 데이터 없음·에러 메시지

| 현황 | 사용자 관점 이슈 | 개선 제안 |
|------|------------------|-----------|
| 탭1만 "일일 운영에서 마감 데이터를 입력해 주세요" 안내 | 탭2~4는 "선택 기간에 데이터가 없습니다"만 있어서 **다음에 뭘 하면 되는지** 모름 | 모든 탭에서 **데이터 없음 시 동일하게** "선택 기간에 데이터가 없습니다. **일일 운영에서 마감 데이터를 입력해 주세요.**" 문구 통일 |
| 메뉴별만 "메뉴별 판매량을 입력해 주세요" | 메뉴별 탭은 원인(메뉴별 입력 누락)이 다르므로 현재처럼 구분 유지 OK | 유지. 필요 시 **일일 운영 페이지로 가는 링크** 추가 |

## 5. 차트 UX

| 현황 | 사용자 관점 이슈 | 개선 제안 |
|------|------------------|-----------|
| 차트 높이 320px(h-80) 고정 | 모바일·작은 창에서 비율이 어색하거나, 데이터 많을 때 눈에 잘 안 들어올 수 있음 | 뷰포트에 따라 **최소 높이 유지 + 필요 시 더 크게** (예: min-h-64, lg:min-h-80) 또는 **차트 영역만 확대 버튼** |
| 90일 선택 시 X축 라벨 | 일별이면 90개 축 라벨이 겹치거나 잘림 | Recharts 기본 동작 확인 후, **일별일 때 tick 수 제한**(예: 최대 10~15개) 또는 **주단위로 묶어서 표시** 옵션 |
| 툴팁 날짜 형식 | "2025-01-05"만 나오면 덜 친숙 | 툴팁에서 **"2025년 1월 5일"** 또는 **"1/5(일)"** 형태로 표시 |
| 탭3 전년 동기 라인 | 전년 데이터가 없으면 라인 없음. 있을 때 구분이 약할 수 있음 | 전년 동기 라인에 **범례 명확화**("전년 동기") + 필요 시 색 구분(예: 회색 계열) |

## 6. 표(테이블) UX

| 현황 | 사용자 관점 이슈 | 개선 제안 |
|------|------------------|-----------|
| 행이 많을 때 스크롤 시 헤더가 사라짐 | 90일 데이터에서 "매출"이 어떤 컬럼인지 다시 찾기 어려움 | **thead sticky** (스크롤 시 상단 고정) 적용 |
| 정렬은 고정(일자 순 등) | "매출 높은 날" 순으로 보고 싶을 때 불가 | **컬럼 헤더 클릭 정렬** (일자·매출·전년대비 등). 우선 **매출 추이·요일별·메뉴별**부터 |
| 메뉴별 표 행 수 | 메뉴가 많으면 스크롤이 길어짐 | **"상위 20개만 보기" / "전체 보기"** 토글이 있으면 첫 사용 시 부담 감소 (선택) |

## 7. 탭별 추가 개선

- **탭1·2 (매출 vs 방문자/결제건수)**  
  - 인당 매출·건당 결제액이 **0이나 비어 있는 날**이 있으면, 툴팁/표에서 **"방문자 0"**, **"결제 0건"** 등 **이유 한 줄** 표시 시 이해하기 쉬움.

- **탭3 (매출 추이)**  
  - 집계 단위(일/주/월)가 **탭 내부**에만 있어서, 첫 방문 시 놓치기 쉬움. **상단 기간 선택 옆**에 "집계: 일별 ▼"를 두거나, 집계 선택 위치를 더 눈에 띄게.

- **탭4 (요일별·주말 vs 평일)**  
  - 요일 순서가 **일→월→…→토**. 주간 시작을 월요일로 쓰는 업무용 사용자는 **월~일** 순이 더 익숙할 수 있음. **설정 또는 토글로 "시작 요일: 일/월"** 선택 (선택 사항).

- **탭5 (메뉴별 매출)**  
  - 파이 차트는 **상위 10개만** 표시. 나머지는 "기타"로 묶어 **비중 %**를 보여주면 "상위 10개가 전체의 80%" 같은 직관이 생김.  
  - **Pie에 "기타" 슬라이스** 추가 + 표에도 "기타 (N개 메뉴)" 행 추가 검토.

## 8. 접근성·일관성

| 항목 | 개선 제안 |
|------|-----------|
| 테이블 | `<table>`에 **caption** 또는 **aria-label**로 "기간별 매출·방문자 표" 등 요약 제공 |
| 차트 | 스크린 리더용 **요약 텍스트** (예: "최근 30일 매출 막대 차트, 총 매출 1,234만 원") 또는 aria-describedby |
| 로딩 | `loading` 중에는 **탭 전환 비활성화** 또는 "데이터 불러오는 중" 안내로 잘못된 탭 클릭 방지 (선택) |

## 9. 새로고침·데이터 갱신

| 현황 | 사용자 관점 이슈 | 개선 제안 |
|------|------------------|-----------|
| 기간만 바꾸면 자동 재조회 | "데이터가 방금 입력됐는데 반영 안 된 것 같다" 할 때 **수동 갱신**이 없음 | **"새로 고침"** 또는 **"데이터 다시 불러오기"** 버튼 추가 (기간 유지한 채 재 fetch) |

## 10. 우선순위 제안 (사용자 체감 기준)

| 순위 | 개선 항목 | 이유 |
|------|-----------|------|
| 1 | 데이터 없음 시 **입력 유도 문구 통일** + (선택) 일일 운영 링크 | 모든 탭에서 "다음 액션"이 같아져 이탈 감소 |
| 2 | **이번 달 / 지난 달** 기간 옵션 | 월 단위 보고가 많아 체감 효과 큼 |
| 3 | **표 thead sticky** | 긴 표에서 컬럼 의미를 잃지 않음 |
| 4 | **교육 배너 접기/펼치기** | 재방문 사용자 UX 개선 |
| 5 | **툴팁 날짜 형식** (년/월/일 또는 요일) | 읽기 편해짐 |
| 6 | **새로 고침 버튼** | 데이터 갱신 타이밍 명확화 |
| 7 | 각 탭 상단 **기간 한 줄 표시** | "지금 어떤 기간인지" 인지 용이 |
| 8 | 탭5 **파이 차트 "기타"** + 표 | 메뉴 많을 때 전체 대비 상위 비중 파악 |

이후에 **사용자 지정 기간**, **컬럼 정렬**, **요일 시작(일/월)** 등은 필요에 따라 단계적으로 적용하면 됩니다.
