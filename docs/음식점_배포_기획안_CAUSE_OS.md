# CAUSE OS · 음식점 사장님 배포 기획안

**제목:** “매출은 운이 아니라 과학이다” — 음식점 경영의사결정 OS  
**대상:** 1인·소규모 음식점 사장님, 프랜차이즈 매장 운영자  
**문서 버전:** 1.0  
**작성 목적:** 앱 도입 이유를 여러 관점에서 정리한 배포·영업용 기획안

---

## 1. 한 줄 요약

**CAUSE OS는 일일 마감·정산·메뉴·발주·QSC(품질·서비스·청결)를 한곳에 모아, 숫자와 품질을 함께 보고 전략까지 이어주는 음식점 전용 경영 대시보드입니다.**

---

## 2. 왜 쓰면 좋은지 — 사용 이유 (다각도)

### 2-1. “숫자로 말하게 하고 싶다” (데이터 기반 경영)

| 니즈 | CAUSE OS가 하는 일 |
|------|---------------------|
| 매출이 왜 오르내리는지 모르겠다 | **매출 흐름 분석**으로 일별·기간별 추이를 그래프로 확인 |
| 이번 달 진짜 벌었는지 헷갈린다 | **손익 구조 분석**으로 매출 대비 비용·이익 구조를 한눈에 파악 |
| 목표만 세우고 잊어버린다 | **목표 대비 분석**으로 월 목표 매출·비용 대비 달성률 추적 |
| 원가·재료비가 너무 나가는지 궁금하다 | **원가·재료 분석**으로 재료비 비율·메뉴별 원가 구조 확인 |
| 어떤 메뉴가 잘 나가는지 감으로만 안다 | **메뉴 구조 분석**으로 메뉴별 매출·판매 비중 시각화 |
| 인건비·인력이 적정한지 모르겠다 | **운영 인력 분석**으로 인력 투입 대비 매출·효율 파악 |

→ **엑셀·수첩 대신 한 화면에서 “숫자로 말하는 매장”**을 만들 수 있습니다.

---

### 2-2. “매일 마감·정산을 습관으로 만들고 싶다”

| 니즈 | CAUSE OS가 하는 일 |
|------|---------------------|
| 마감을 자주 빼먹거나 나중에 몰아서 한다 | **일일 운영(일일 마감)** 화면으로 “오늘 마감했는지” 체크하고 일 매출·메뉴별 매출 입력 |
| 정산이 매월 한 번씩만 되고, 중간에 흐름을 모른다 | **정산 관리**로 월별 정산 데이터 입력·비교, **대시보드**에서 최근 일 매출 추이 확인 |
| 목표 매출을 세우지만 기록이 없다 | **목표 관리**로 월별 목표 매출·비용 비율 설정 후, 분석·전략 화면에서 달성 여부 확인 |

→ **매일 5분, 마감 습관**이 쌓이면 나중에 “왜 그달이 좋았/나빴는지”를 설명할 수 있습니다.

---

### 2-3. “손익분기점·고정비를 알고 운영하고 싶다”

| 니즈 | CAUSE OS가 하는 일 |
|------|---------------------|
| 얼마나 팔아야 본전인지 모른다 | **데이터 전략 센터**에서 임차료·인건비·재료비 등으로 **손익분기점(BEP)** 자동 계산 |
| 고정비·변동비를 구분해서 보지 못한다 | 전략 센터에서 **임차료, 인건비, 재료비, 공과금, 부가세·카드수수료** 등 항목별 입력·비율로 구조 파악 |
| “이번 달 목표 매출”을 근거 있게 세우고 싶다 | 목표 매출·비용 비율을 넣고 BEP·목표 이익 역산으로 **근거 있는 목표** 설정 |

→ **감이 아닌 숫자로 “이만큼은 팔아야 한다”**는 기준을 갖게 됩니다.

---

### 2-4. “품질·서비스·청결(QSC)을 체계적으로 관리하고 싶다”

| 니즈 | CAUSE OS가 하는 일 |
|------|---------------------|
| 맛·서비스·청결을 말로만 강조하고 끝난다 | **QSC 입력**으로 일일 점검·오디트 항목을 체크리스트처럼 기록 (실패/개선 항목 표시) |
| 우리 매장이 어떤 부분이 약한지 모른다 | **QSC 분석**에서 Q·S·C·공간·가격·상권·마케팅·인재·재무 등 **9가지 요소** 레이더 차트로 강·약점 시각화 |
| 문제만 쌓이고 실행 계획이 없다 | **QSC 전략센터**에서 “집중 개선 항목”을 선정해 **실행 계획(Action Plan)** 으로 연결 |
| 프랜차이즈 본부 점검 대비가 하고 싶다 | QSC 입력·분석으로 **자체 점검 이력**을 쌓아, 본부 점검 전에 미리 보완 가능 |

→ **숫자(매출·원가) + 품질(QSC)** 를 같이 보는 “경영의사결정”이 가능해집니다.

---

### 2-5. “메뉴·재료·발주를 정리하고 싶다”

| 니즈 | CAUSE OS가 하는 일 |
|------|---------------------|
| 메뉴가 바뀔 때마다 어디에도 정리되지 않는다 | **메뉴 관리**에서 메뉴 등록·재료 연결·레시피(조리법) 정리 |
| 재료를 등록해 두고 원가·발주에 쓰고 싶다 | **메뉴 관리** 내 **재료 등록**으로 재료 마스터 구성 후, 발주·원가 분석과 연결 |
| 발주를 감으로만 하거나 잊어버린다 | **발주 관리**에서 발주 등록·재고 참고·안전재고·발주 참고 탭으로 발주 습관화 |
| 정산과 매출을 같이 보고 싶다 | **정산 관리**에서 월별 정산 입력·비교, **정산 vs 매출** 흐름을 분석·대시보드와 함께 활용 |

→ **메뉴·재료·발주가 한 흐름**으로 이어져, 나중에 원가·매출 분석의 기초가 됩니다.

---

### 2-6. “시간은 부족한데, 중요한 것만 보고 결정하고 싶다”

| 니즈 | CAUSE OS가 하는 일 |
|------|---------------------|
| 매일 들어가서 확인할 화면이 따로 없다 | **대시보드**에서 “오늘 마감 여부”, “최근 일 매출 추이”, “입력 현황(마감/목표/정산 등)” 한눈에 확인 |
| 입력은 팀원이 하고, 나는 결과만 보고 싶다 | 대시보드 + **분석 센터**만 주로 보면 “입력된 숫자”의 요약·추이만 집중해서 볼 수 있음 |
| 다음에 뭘 해야 할지 앱이 알려주면 좋겠다 | **입력 센터**에서 “오늘 마감 안 함”, “이번 달 목표 미설정” 등 **할 일 안내**로 다음 액션 유도 |

→ **바쁜 사장님이 “매일 5분, 한 화면”**으로 상태를 점검할 수 있도록 설계할 수 있습니다.

---

### 2-7. “여러 매장·팀원과 같이 쓰고 싶다” (확장 시나리오)

| 니즈 | CAUSE OS가 하는 일 |
|------|---------------------|
| 매장별로 데이터가 나뉘었으면 좋겠다 | **매장(store) 단위**로 데이터 분리 가능 (가게정보등록·멤버 연결) |
| 점장·알바가 마감·QSC 입력만 하고, 사장은 분석만 보고 싶다 | **역할별 화면** 구성: 입력 담당자는 입력 센터·QSC 입력, 사장님은 대시보드·분석·전략 센터 위주 사용 |
| 나중에 본사·프랜차이즈에도 쓰고 싶다 | 동일 앱으로 **다매장 대시보드·다매장 QSC 비교** 등 확장 기획 가능 |

→ **1인 매장에서 시작해, 다매장·팀 운영**까지 확장할 수 있는 구조입니다.

## 3. 타깃별로 보는 “쓰는 이유” 요약

| 타깃 | 한 줄 이유 |
|------|-------------|
| **1인·소규모 음식점 사장님** | 매일 마감·정산·목표를 한곳에 모아, “숫자로 말하는 매장”으로 바꾸고 싶을 때 |
| **손익분기점·고정비를 알고 싶은 사장님** | BEP·목표 매출을 계산해서 “얼마나 팔아야 하는지” 기준을 갖고 싶을 때 |
| **품질·서비스·청결을 체계 관리하고 싶은 사장님** | QSC를 체크리스트·레이더 차트·전략으로 이어서 “품질 경영”을 하고 싶을 때 |
| **메뉴·재료·발주를 정리하고 싶은 사장님** | 메뉴·재료·발주를 등록해 두고, 원가·매출 분석의 기초를 만들고 싶을 때 |
| **시간이 없어서 핵심만 보고 싶은 사장님** | 대시보드 한 화면 + 분석만으로 “오늘 상태·최근 추이”를 빠르게 보고 싶을 때 |
| **프랜차이즈·다매장 운영자** | 매장별 데이터·QSC 이력으로 비교·점검 체계를 갖추고 싶을 때 (확장 시나리오) |

## 4. 앱 구조와 “쓰는 이유” 매핑

| 메뉴(기능) | 사장님이 쓰는 이유 (한 줄) |
|------------|----------------------------|
| **홈 / 대시보드** | 오늘 마감 여부·최근 매출·입력 현황을 한눈에 보려고 |
| **입력 센터** (일일운영·근무·메뉴·발주·정산·목표) | 매일 마감·정산·목표·메뉴·발주를 습관처럼 입력하려고 |
| **분석 센터** (매출·손익·목표·원가·메뉴·인력) | “왜 그랬는지”를 숫자·그래프로 이해하려고 |
| **데이터 전략 센터** | 손익분기점·목표 매출·비용 구조를 계산해 근거 있는 목표를 세우려고 |
| **QSC** (소개·입력·분석·전략) | 품질·서비스·청결을 기록하고, 약점을 찾아 실행 계획까지 이으려고 |
| **가게정보등록** | 우리 매장 단위로 데이터를 나누고 팀원을 붙이려고 |

## 5. 배포·영업 시 강조할 메시지 (선택)

- **“매출은 운이 아니라 과학이다”** — CAUSE OS가 제공하는 9가지 핵심 요소(QSC 등)와 숫자 기반 분석으로 “운”이 아닌 “관리”로 매출을 만든다는 메시지.
- **“매일 5분, 마감 습관”** — 일일 마감·정산 입력의 진입 장벽을 낮추고, 습관이 쌓이면 분석·전략의 가치가 커진다는 점.
- **“숫자 + 품질, 한곳에서”** — 매출·손익·원가뿐 아니라 QSC까지 한 앱에서 보고, 전략(손익분기점·집중 개선 항목)까지 이어준다는 점.
- **“1인 매장에서 다매장까지”** — 지금은 1인·소규모에 최적화되어 있지만, 매장 단위·역할 분리 구조로 나중에 다매장·프랜차이즈로 확장 가능하다는 점.

## 6. 정리

- **사용 이유**는 위와 같이 **데이터 기반 경영, 일일 마감·정산 습관, 손익분기점·전략, QSC 체계 관리, 메뉴·재료·발주 정리, 시간 절약, 다매장·팀 확장** 등으로 나눌 수 있습니다.
- 배포 시에는 **타깃(1인 사장님 / 프랜차이즈 등)** 과 **니즈(숫자 보고 싶다 / QSC 관리하고 싶다 등)** 에 맞춰 2~3가지 이유를 골라 강조하는 것이 효과적입니다.

이 기획안을 바탕으로 **랜딩 페이지 문구, 상담 시나리오, 온보딩 플로우** 등을 이어서 설계할 수 있습니다.
